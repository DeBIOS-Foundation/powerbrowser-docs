# Choosing a PowerBrowser extension surface

> Verified against PB 8843936 on 2026-10-21. Level: source-read

Source files:
- `$PB_REPO/powerbrowser/shell/PowerBrowserAPI.sys.mjs`
- `$PB_REPO/powerbrowser/INTERNAL-APIS.md`
- `$PB_REPO/powerbrowser/endpoint-allowlist.json`
- `$PB_REPO/scripts/verify-endpoints.sh`
- `$PB_REPO/scripts/lib/firefox-bidi.mjs`
- `$PB_REPO/scripts/lib/pb-live-probe.mjs`
- `$PB_REPO/theia/extensions/tab-uris/src/browser/tab-store-access-protocol.ts`
- `$PB_REPO/theia/extensions/chrome-bar/src/browser/chrome-bar-shortcuts.ts`

- `$PB_REPO/configuration.toml`

Each row names one surface. The linked doc has the exact API, payloads and build steps, and carries its own stamp; this page states facts directly only for the files listed above. "Theia extension" means a compile-time `@powerbrowser/<name>` package under `$PB_REPO/theia/extensions/`. It only exists after a PB rebuild.

| Task you want to do | Surface | Doc file | Why |
|---|---|---|---|
| Add a panel, view or widget inside the PB shell | Theia extension (`WidgetFactory` + `bindViewContribution`) | [01-theia-extensions.md](01-theia-extensions.md) | Only Theia extensions and plugins render UI in the shell window. WebExtension UI does not appear there. |
| Add a command, menu item or keybinding to the shell | Theia extension (`CommandContribution`, `MenuContribution`, `KeybindingContribution`) | [01-theia-extensions.md](01-theia-extensions.md) | Binding is static at module load (D-50). A contribution bound later is never seen. A Theia keybinding does not fire while a web page has focus; browser keys there are the page-scoped rows (`PAGE_SHORTCUTS`), see [Commands and keybindings touching tabs](09-tabs-reference.md#commands-and-keybindings-touching-tabs). |
| Run an existing PB command (switch mode, open a stock window, new group) | `CommandService.executeCommand` with an exported id constant | [01-theia-extensions.md](01-theia-extensions.md) | Reuses PB behaviour without new code. The id constants are exported next to each `Command`. |
| Add a UI command that needs no PB rebuild and no PB DI services | VS Code plugin (`.vsix`) pinned with `[[extensions]]` | [06-theia-plugins-and-ai.md](06-theia-plugins-and-ai.md) | It is installed at build time with a sha256 pin and runs in the plugin host. It cannot inject `TabUriRegistry` or the other PB DI services. |
| Read open tabs, groups or tab URIs from Theia code | Inject `TabUriRegistry`, `GroupQueryService`, `GroupModel` | [01-theia-extensions.md](01-theia-extensions.md) | Read-only services that already exist. Never open `tabs.sqlite` yourself. |
| Create, rename, move or dissolve groups, or move tabs between groups, from Theia code | `GroupModel` methods (which call `GroupActorClient.mutate`) | [01-theia-extensions.md](01-theia-extensions.md), [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | Only chrome writes `tabs.sqlite`. `GroupModel` keeps the in-memory model and the store in sync. |
| Drive a web tab (reload, hard reload, stop, back and forward, session history) | `WebTabWidget` methods `reload(bypassCache)`, `stop()`, `history()`, `gotoIndex(index)` (kinds `webTabReload`, `webTabStop`, `webTabHistory`, `webTabGotoIndex`) | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md), [09-tabs-reference.md](09-tabs-reference.md) | Chrome owns the overlay browser that renders the page; the widget sends each kind over `WebTabChannel`. |
| React to web-tab state, page focus or a page-scoped key | `WebTabChannel.onPush(kind, handler)` (push kinds `state`, `pageFocus`, `shortcut`, `flushShellState`) | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | One chrome push event carries every kind; subscribe per kind instead of adding a window listener. |
| Read history or bookmarks, or search Places, from Theia code | `ChromeStoreClient` (`readHistoryEntry`, `searchPlaces`, `listBookmarkFolder`, and so on) | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | Places is held by Firefox chrome. The `PowerBrowserGroup` actor is the only channel to it. The one Places write, `removeHistoryEntry`, is a privileged kind that only the chrome bar's widget may send; a Theia extension has no history or bookmark write through the bridge. |
| Resolve typed text to a visit or a search, list the address-bar search engines, get search-engine suggestions for typed text, or complete typed text to a visited origin | `ChromeStoreClient.resolveTypedAddress(text, engineName, canonize)`, `ChromeStoreClient.listSearchEngines()`, `ChromeStoreClient.searchSuggestions(text, engineName)`, `ChromeStoreClient.autofillOrigin(text)` | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | URI fixup, the search engines and the suggestion fetch live in chrome (`resolveTypedAddress`, `listSearchEngines`, `searchSuggestions` and `autofillOrigin` in `$PB_REPO/powerbrowser/shell/PowerBrowserAPI.sys.mjs`). None of the four kinds is relayed to MCP. |
| Open a URL in a stock Firefox tab or window | Command `powerbrowser.open-browser-window`, or the `openStockTab` kind | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | It accepts only http(s) and `about:newtab`. Read `where` in the reply, because `ok:true` can still be a refusal. |
| Save a copy of a page to disk | `ChromeStoreClient.savePageCopy(uri)` or command `powerbrowser.tab.savePageCopy` | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | The copy is written under `<profile>/saved-pages/`. Use a 120 s timeout. |
| Read or modify the DOM of web pages, inject content scripts, or filter network requests | Firefox WebExtension installed by policy (`[[webextensions]]`) | [05-webextensions.md](05-webextensions.md) | Content scripts and `webRequest` belong to the stock engine. The other surfaces cannot access page content. |
| Install a third-party Firefox add-on | `[[webextensions]]`, then copy into `policies.json` `ExtensionSettings` | [05-webextensions.md](05-webextensions.md) | The policy install is the only supported path. A sideloaded add-on arrives disabled, and `about:addons` cannot be reached from Theia. |
| Install a third-party VS Code / Open VSX extension | `[[extensions]]` (sha256-pinned) | [06-theia-plugins-and-ai.md](06-theia-plugins-and-ai.md) | Reproducible build-time install. A runtime Open VSX install is not pinned and does not ship. |
| Run Node-only code (file system, child processes, SQLite reads) for a Theia UI | Backend JSON-RPC service at `/services/powerbrowser/<name>` | [04-theia-backend-rpc-http.md](04-theia-backend-rpc-http.md) | It uses the existing token-gated WebSocket, so it needs no new HTTP route and no token-gate review. |
| Have the backend call into a Theia window | Relay pattern (`JsonRpcConnectionHandler` with client proxy, like `tab-store-relay`) | [04-theia-backend-rpc-http.md](04-theia-backend-rpc-http.md) | The backend has no channel to chrome of its own. It must go through an open window. |
| Read the profile dir or another supervisor value in backend code | `POWERBROWSER_ENV` from `@powerbrowser/token-gate` | [04-theia-backend-rpc-http.md](04-theia-backend-rpc-http.md) | `process.env.POWERBROWSER_*` is scrubbed at backend load and is always empty. |
| Call an external web API from an extension | Code in your extension, plus a `hosts` row in `$PB_REPO/powerbrowser/endpoint-allowlist.json` | [04-theia-backend-rpc-http.md](04-theia-backend-rpc-http.md) | `$PB_REPO/scripts/verify-endpoints.sh` fails on any egress host that has no row. |
| Give an external AI agent (Claude Code, a script) access to tabs, groups, history and bookmarks | Tab-store MCP endpoint (`POST /mcp`, `store-access.json`) | [03-tab-store-mcp-server.md](03-tab-store-mcp-server.md) | It is the only PB API reachable from outside the browser. Its tools (`TAB_STORE_TOOL_NAMES` in `$PB_REPO/theia/extensions/tab-uris/src/browser/tab-store-access-protocol.ts`) include read-only SQL (`tabs_sql`) and `tab_store_write`. It cannot reach the web-tab kinds, `resolveTypedAddress` or `listSearchEngines`. |
| Expose a new kind of data to external agents | New tool in `TAB_STORE_TOOL_NAMES` / `TOOLS`, or a new `tab_store_write` op | [03-tab-store-mcp-server.md](03-tab-store-mcp-server.md) | Extend the existing endpoint. Do not add a route to the cookie-gated Theia port. |
| Expose a new external HTTP API that is not MCP | New loopback listener that copies `TabStoreAccessEndpoint` (bearer token, Origin/Host walls, 0600 access file) | [04-theia-backend-rpc-http.md](04-theia-backend-rpc-http.md) | The Theia port admits only the per-launch cookie, by design. |
| Give Theia AI chat a tool | `ToolProvider` + `bindToolProvider` in a Theia extension frontend module | [06-theia-plugins-and-ai.md](06-theia-plugins-and-ai.md) | `ToolInvocationRegistry` exists only in the frontend container. AI is off until the user sets `ai-features.AiEnable.enableAI`. |
| Give Theia AI a tool from a plugin | `vscode.lm.registerTool` plus `contributes.languageModelTools` | [06-theia-plugins-and-ai.md](06-theia-plugins-and-ai.md) | Bridged into the same registry. `createChatParticipant` and `registerLanguageModelChatProvider` are stubs. |
| Connect Theia AI to an existing MCP server | User preference `ai-features.mcp.mcpServers` | [06-theia-plugins-and-ai.md](06-theia-plugins-and-ai.md) | Needs no code. Tools register as `mcp_<server>_<tool>`. |
| Add a chat agent or a language-model provider | `AbstractStreamParsingChatAgent` / `LanguageModelProvider` in a Theia extension | [06-theia-plugins-and-ai.md](06-theia-plugins-and-ai.md) | DI contribution points of `@theia/ai-chat` / `@theia/ai-core`, pinned at 1.76.0 in `$PB_REPO/theia/applications/browser/package.json`. |
| Add a new Firefox capability (prefs, window control, a new Places query) for Theia | New message `kind` in one of the four dispatchers of `$PB_REPO/powerbrowser/shell/PowerBrowserAPI.sys.mjs`, plus a row appended to `$PB_REPO/powerbrowser/INTERNAL-APIS.md` for each new Firefox internal it touches | [02-powerbrowser-api-bridge.md](02-powerbrowser-api-bridge.md) | Hard rule 2 makes this the only file allowed to touch Firefox internals. This is a PB core change, not an extension. INTERNAL-APIS.md also has an `Append-only rule` and a `Privileged-kind rule` for new kinds. |
| Restyle the shell (theme, CSS) | `$THEIA_CONFIG_DIR/customize.css` (default `${XDG_CONFIG_HOME:-$HOME/.config}/powerbrowser/customize.css`) | [01-theia-extensions.md](01-theia-extensions.md) | No build is needed and it reloads live. For a shipped theme, use a Theia extension or a theme `.vsix`. |
| Run privileged user scripts against the DI container | `customize.js` (present-but-disabled; build flag `powerbrowserPrivilegedJs`) | [01-theia-extensions.md](01-theia-extensions.md) | Do not ship it enabled, because `verify-branding` fails. For prototyping, use `window.theia.container` from devtools. |
| Collect usage or error events | Inject `PowerBrowserTelemetryLogger` | [01-theia-extensions.md](01-theia-extensions.md) | It honours `telemetry.telemetryLevel` (shipped `off`, endpoint `null`). |
| Automate end-to-end tests against the real binary | WebDriver BiDi through `$PB_REPO/scripts/lib/firefox-bidi.mjs` (`withFirefoxPage`); for keys that must reach a chrome `<key>`, the live-probe harness `$PB_REPO/scripts/lib/pb-live-probe.mjs` | [07-automation-and-disabled-surfaces.md](07-automation-and-disabled-surfaces.md) | PB's own live checks use these helpers. BiDi content input never fires the page-scoped keys, so key tests synthesise keys at the parent. CDP is absent, and Marionette and geckodriver are unsupported for checks. |
| Debug chrome code or the Theia frontend interactively | Browser Toolbox (`--jsdebugger`) / DevTools | [07-automation-and-disabled-surfaces.md](07-automation-and-disabled-surfaces.md) | `devtools.chrome.enabled` is already `true` in PB builds. |
| Let pages register tools for an agent (WebMCP) | `navigator.modelContext`, dev profile only | [07-automation-and-disabled-surfaces.md](07-automation-and-disabled-surfaces.md) | It is disabled by pref, has no consumer, and is out of scope to ship. |

## Capability gaps (no surface supports these yet)

- Read page DOM or page text from Theia or from an external agent. No actor kind or MCP tool returns page content. Building it requires a new store kind in `$PB_REPO/powerbrowser/shell/PowerBrowserAPI.sys.mjs`, plus a relay kind and MCP tool if agents need it, or a WebExtension that reports to a loopback listener.
- Open, close or navigate tabs from an external agent. MCP has no navigation tool and excludes `closeGroup`. Building it requires new tools plus chrome kinds that reach `openStockTab` and the web-tab kinds; `TAB_STORE_RELAY_KINDS` holds no web-tab kind and [03-tab-store-mcp-server.md](03-tab-store-mcp-server.md) says not to add one, so this is a PB core design change (see [Rules and constraints](03-tab-store-mcp-server.md#rules-and-constraints)).
- WebExtension UI in the Theia shell. Browser actions, popups and sidebars render only in stock windows. Building it requires shell chrome, which is blocked by rule 5 ("no custom browser chrome is authored").
- WebExtension access to PB tab/group data, or to the in-shell web tabs. There is no bridge. UNVERIFIED: whether `browser.tabs` sees in-shell web tabs. Verify: load a temporary add-on in a PB build that logs `browser.tabs.query({})` while web tabs are open. Building it requires a native-messaging host or a loopback client of the MCP endpoint.
- A `powerbrowser.*` API namespace for `.vsix` plugins. The `extPluginApi` hook exists, but nothing is built and the design note is superseded.
- Theia exposed as an MCP server. `@theia/ai-mcp-server` is not a dependency in `$PB_REPO/theia/applications/browser/package.json`. Adding it at 1.76.0 is a PB core change.
- Theia AI using PB's own tab-store MCP endpoint. Port and token change on every start, so a static `mcpServers` entry goes stale. UNVERIFIED: that Theia AI can use the endpoint end to end. Verify: configure `ai-features.mcp.mcpServers` from the current `store-access.json` in a PB build and call a tab-store tool from chat. Building it requires an extension that rewrites the preference or registers tools from `store-access.json` at startup.
- Push events to external agents. The MCP endpoint has no SSE, no sessions and no change notifications, so clients must poll.
- Remote (non-loopback) access to any PB API. All listeners are loopback-only by design (SIDE-01).
- Passing a URL to a running instance. `PowerBrowserSingleInstanceHandler` drops all arguments when a shell window exists.
- Shipping unsigned add-ons. There is no key in `$PB_REPO/configuration.toml` for `xpinstall.signatures.required`.
- Runtime install of Theia-native extensions. Every `@powerbrowser/*` extension needs a PB rebuild.

Scope note: PB's planning files list "DSH (DeepSeek Harness) and any AI assistant integration" and "Customising Theia's AI framework" (stays stock until a later milestone, RM-02) as Out of Scope; at the stamped PB commit they sit in `$PB_REPO/.planning/PROJECT.md`, section "Out of Scope". UNVERIFIED: this scope decision rests only on PB planning files, which can lag. Verify: read `$PB_REPO/.planning/PROJECT.md` section "Out of Scope" at your PB HEAD and ask the user. Confirm with the user before shipping AI tools or agents into PB core.
